# 系统运维与代理更新

## 1. 部署结构

- 网页与API运行在`h3-console`容器，端口8926。
- `data/`挂载到容器`/data`，保存数据库、视频、首尾帧、更新请求和私密网络设置。
- 宿主机更新代理`/usr/local/sbin/h3-console-update-agent`由cron每分钟检查一次更新请求。
- GitHub保存代码、文档和固定参考图，不保存`data/`中的运行数据与秘密。

## 2. GitHub版本检测为什么会失败

版本检测访问`raw.githubusercontent.com`。在部分服务器网络中可能因跨境线路、DNS、防火墙、连接超时或GitHub临时故障失败，不能只凭一次失败断定GitHub不可用。

系统管理中的“网络通道”支持以下代理：

- `http://主机:端口`
- `https://主机:端口`
- `socks5://用户名:密码@主机:端口`
- `socks5h://用户名:密码@主机:端口`

保存后，网页版本检测自动通过代理访问GitHub；宿主机更新代理执行`git fetch`时读取同一份Git代理配置。

## 3. 安全边界

- 代理完整地址只保存在服务器`data/network-settings.json`，文件权限0600。
- Git使用的私密配置保存在`data/git-proxy.config`，文件权限0600。
- API和界面只返回脱敏后的主机与端口，不返回用户名或密码。
- 代理地址、服务器密码、API密钥和Cookie禁止提交GitHub。
- 修改代理前先点“测试连接”；测试成功后再保存。
- 代理来源不可信时不要使用，因为代理运营者可能观察连接目标与流量元数据。

## 4. 更新流程

1. 系统管理调用GitHub版本检测；启用代理时自动使用已保存代理。
2. 管理员确认更新后，网页只在`data/`创建更新请求。
3. 宿主机代理读取`data/git-proxy.config`执行`git fetch`与快进合并。
4. Docker重新构建并启动容器；`data/`不会被覆盖。
5. 更新结果写入`data/update-status.json`并显示在系统管理中。

## 5. 首次启用新版更新代理

升级到包含代理功能的版本后，在项目目录执行一次：

```bash
sudo bash scripts/install-update-agent.sh "$PWD"
```

旧版宿主机代理不知道如何读取`git-proxy.config`，所以这一步不能省略。以后脚本会在每次成功更新时自动替换自身。

## 6. 排错顺序

```bash
docker compose ps
docker compose logs --tail=100 h3-console
cat data/update-status.json
tail -100 data/update-agent.log
curl http://127.0.0.1:8926/api/health
```

界面显示“代理已保存”但检测失败时，依次检查代理是否到期、主机端口是否可达、用户名密码是否正确、协议是否选对。不要把完整代理密码粘贴到公开Issue或日志中。
